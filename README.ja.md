# meeting-coach

**会議の準備から振り返りまでを、ひと続きで回す**　Claude 用の Agent Skill です  会う相手を公開情報から調べて聞くことを組み立て、会議のあとは文字起こしから100点満点で採点します  減点には必ず発言の引用が付きます  学んだことは手元に残り、次の会議の前に「今回意識すること」として戻ってきます

[English README](README.md)

```
 準備 ──▶ 会議 ──▶ 振り返り ──▶ 次の準備
  │                   │
  │ 調査・聞くこと     │ 2つの点数 /100・引用・「伝わったか」
  │ 過去の学び         │ 準備との照合・次回の行動 1〜3個
  └──── ~/.meeting-coach にローカル保存 ────┘
```

## できること

**会議の前**
- 相手の情報を公開情報 (所属組織のページ・登壇・インタビュー) から集め、事実ごとに出典を付けます  社外の相手なら、相手の会社の最近の動きも調べます
- 経歴の年表と「相手の読み解き」を出します  中身は、本人の言葉で語られた大事にしていること・今の関心・自分との接点・刺さる伝え方と避けたいことです
- 冒頭の一言と、聞くこと5〜7問を出します  入り → 本題 → 締めの順に並べ、目的と相手自身の言葉に結び付けます  過去の振り返りから選んだ「今回意識すること」も付けます
- 前回の議事録を渡すと、決まったこと・お互いの宿題・聞き直さなくてよいことを整理します

**会議のあと**
- **会議点 /100** (会議そのものの出来) と **自分点 /100** (自分のふるまい) を別々に出します  2つを混ぜることはしません
- 減点の根拠は、文字起こしからの引用か、言うべきことが無かった箇所の範囲です  引用は実在するかを機械で照合します  時間超過は時刻から計算します
- 「伝わったか」の兆候を出します  長い説明への相槌だけの返事、担当も期日も付かない「検討します」、質問が返ってこない、締めが曖昧、などです  文脈で判定し、断定ではなく兆候として示します
- 準備との照合で、予定した問いを実際に聞けたかを確かめます
- 次回の行動を1〜3個出します  次の会議で「できたか」を確かめられる形で書きます

### 採点のしくみ
AI が決めるのは、観点ごとの **水準 (0〜4) と根拠の引用だけ** です  点数は固定の重みでスクリプトが計算するので、同じ判定からは必ず同じ点数が出ます

- 時間超過は会議点から減点します  自分点から減点するのは、自分が進行役だったときだけです
- 入力から判断できない観点 (話者の区別が無いなど) は「採点不能」とし、0点ではなく分母から外します
- 採点基準は、会議・1on1 (上司側・部下側・同僚)・社外の種類ごとに変えています
- 重み・バンド・減点幅はすべて **設計上の初期値で、研究の結果ではありません**  `~/.meeting-coach/config.json` で変えられます

### 言語
日本語と英語に対応しています  日本語の「はい」が実は「まだ」を意味する、といった婉曲な表現も判定します  ほかの言語は言語ファイルを追加すれば対応できます

## 導入

**Claude Code**
```text
/plugin marketplace add ry071702-prog/meeting-coach
/plugin install meeting-coach@meeting-coach
```

**Claude.ai**　[Releases](../../releases) から `meeting-coach.zip` をダウンロードし、*設定 → 機能 → スキル* でアップロードします  Claude.ai ではチャットをまたいでファイルを残せません  そのため、準備と振り返りの最後に短いブロック (癖・未完の行動・照合前の準備) を出します  次のチャットの最初に貼ってください  また Claude.ai ではスクリプトがネットワークに出られないため、プロフィールは Claude 自身の Web 機能で読みます

**ブラウザで使う (導入不要)**　[Web アプリ](https://ry071702-prog.github.io/meeting-coach/) を開き、「設定」で使う AI を選んで、その AI の自分の API キーを入れます  採点のスクリプトは skill と同じものをブラウザ内 (Pyodide) で動かし、選んだ AI の API へはブラウザから直接送ります  利用料が発生する場合は、その AI の会社からキーの持ち主に請求されます  API キーと会議の内容は、作者を含めほかの誰のサーバーも通りません  点数・学び・準備はそのブラウザにだけ残ります  別の端末へ移すときは「履歴 → バックアップを保存」を使ってください

| AI | キーの取得先 | 既定のモデル | 実際の API での確認 |
|---|---|---|---|
| Claude (Anthropic) | [Claude Console](https://platform.claude.com/settings/keys) | Claude Opus 5.5 | 未確認 |
| OpenAI | [OpenAI Platform](https://platform.openai.com/api-keys) | GPT-6 Astra | 未確認 |
| Gemini (Google) | [Google AI Studio](https://aistudio.google.com/apikey) | Gemini Flash | 確認済み (2026-10-15、`gemini-flash-latest`、`examples/` の架空の会議)  ただし試験的で、採点し直すとバンドが1段ずれることがある  準備では Web を検索せず、渡した URL だけを読む |

同じ会社のほかのモデルも、名前を入れれば選べます  ただし、推論の深さの設定を受け付けないモデルは、API 側でエラーになることがあります  Claude と OpenAI は、API のモックでしか動かしていません  うまく動かないときは [Issues](../../issues) で知らせてください

> **Gemini の無料枠について**　課金を設定していないキーで送った内容は、Google が製品の改善に使い、人が読むこともあります ([Gemini API の規約](https://ai.google.dev/gemini-api/terms))  Gemini を選んでいる間は、画面にも注意を出します  実際の会議には、課金を有効にしたキーを使ってください

**SKILL.md を読めるほかのエージェント** (Codex など)　`skills/meeting-coach` をそのエージェントの skill フォルダに置きます

必要なもの: Python 3.9 以上 (標準ライブラリのみ)  Web での調査には、エージェント側に Web 検索の機能が必要です

## 使い方

- 「明日の山田さんとの1on1の準備をして  プロフィールは <URL>  来期の目標をすり合わせたい」
- 「この会議を採点して」+ 文字起こしのファイルか貼り付け

対応する文字起こし (テキストファイルで渡してください  .docx や PDF のメモは .txt に書き出してから)
- Google Meet (Gemini のメモ)
- Zoom・Teams の `.vtt`
- Otter 形式
- `名前: 発言` 形式の記録
- 話者の区別が無いテキスト (文脈から話者を割り当て、自分点は参考値として出します  引用は保存しません)

**録画・音声** は、手元の Whisper (Apple Silicon なら `mlx-whisper`、それ以外は `openai-whisper`) と ffmpeg で文字起こしします  音声はどこにも送りません  発言の時刻がとれるので、質問の後の沈黙も測れます  話者は文脈から割り当てるため、自分点は参考値になります  また、ごく短い返事は音声認識で落ちることがあります  Claude.ai と Web 版では使えません

## プライバシー
- 文字起こしは、使っている AI サービスとの会話の一部として渡ります (Claude.ai なら Claude.ai にアップロードされます)  skill のスクリプトは、それ以外のどこにも送りません
- Web アプリでは、API キーと会議の内容がブラウザから、選んだ AI の会社 (Anthropic・OpenAI・Google のいずれか) に直接送られます  画面と採点のスクリプトはこのサイトから、ライブラリ (Python の実行環境・Markdown の表示・HTML の無害化・Anthropic の SDK) は jsDelivr から読み込みます  準備では、相手の名前・所属・URL を AI に渡します  Claude と OpenAI はそれを Web 検索に使い、Gemini は渡した URL のページを読むだけです (Gemini の Google 検索を使う条件を、このアプリでは満たせないと判断したため)  保存先は `~/.meeting-coach/` でなくそのブラウザ (IndexedDB) で、残すものと残さないものは下と同じです
- `~/.meeting-coach/` に残すもの: 点数・水準・本人のものと確認できた自分の発言の引用・次回の行動・癖、そして準備で立てた目的と問いの狙い
- 残さないもの: 判定の理由・調査メモ・プロフィールの本文・相手の発言  相手の発言の丸写しは保存する文から消しますが、短い断片や言い換えは残ることがあります
- 相手の名前は役割名に置き換えます  ただし完全ではありません  会話の中で名前だけ出てくる第三者や、表示名と呼び名が違う参加者 (別表記を skill に伝えれば消せます) は残ることがあります
- 調べるのは公開された仕事上の情報だけです  個人の SNS・家族・健康・政治などは調べません  同姓同名の取り違えを防ぐため、名前に加えてもう1つの手がかりが一致する情報源だけを使います
- 録音のルールや職場の規程は場所によって違います  録音の前に相手の同意を取ってください  文字起こしや同僚の情報を AI に渡す前に、所属先のルールも確かめてください

## 設定

`~/.meeting-coach/config.json` で [`config.default.json`](skills/meeting-coach/config.default.json) のどの項目でも上書きできます

| 項目 | 内容 |
|---|---|
| `rubrics` `bands` `time_penalty` | 重み・バンドの境目・時間超過の減点 |
| `research_budget` | 人・会社ごとの Web 検索の上限 (`learnings.py config` で今の値を確認できます) |
| `notes_dirs` | 自分の議事録フォルダ  続きの面談の前に相手の名前で探します |
| `org_pack` | 組織パックの場所 (下記) |
| `redact_names` | 保存するファイルで参加者の名前を役割名に置き換える (既定 `true`) |

### 組織パック
組織パックは、自分の組織が社員の情報をどこで公開しているか (社員紹介・オウンドメディア・登壇ページ) と、その読み方を書いた Markdown です  このリポジトリの外に置き、`org_pack` でその場所を指定します  書き方は [`examples/org-pack-example.md`](examples/org-pack-example.md) を見てください

## 開発
```bash
python3 -m unittest discover tests
node --test 'tests/providers/*.test.mjs'   # Web 版の AI の呼び出し (Node 22 以上)
bash tests/e2e/run.sh                      # Web 版の通し確認  AI の API はモック (Docker が必要)
```
`examples/` の文字起こしはすべて架空です  実際の会議をこのリポジトリに入れないでください
